The module is split into a backend Express API and a React/Vite frontend under one monorepo root.

- Backend (`backend/src`): A standard Express app with layered routing — `routes/admin.ts` exposes all admin endpoints under `/api/admin/*`, guarded by `middleware/adminAuth.ts` which verifies a JWT and checks `user.isAdmin`. Routes are organized by domain: `auth.ts`, `claims.ts`, `garage.ts`, `garageAuth.ts`, `policies.ts`, `vehicles.ts`, `generalChat.ts`. Business logic is delegated to `services/` (claim assistant, damage analysis, document verification, repair estimate, vehicle detection) and shared via `utils/prisma.ts` (Prisma client) and `utils/gemini.ts` (Google AI). Data access is defined in `prisma/schema.prisma` using SQLite, with enums for `ClaimStatus`, `VerificationStatus`, `DocumentType`, etc., and an `AdminNote` model for per-claim admin annotations.
- Frontend (`frontend/src`): A React SPA built with Vite and Tailwind. The admin UI lives under `pages/admin/` (Dashboard, Claims, Claim Detail, Documents, Users, Garages, Login) and is gated by `components/AdminProtectedRoute.tsx`, which checks a stored `adminToken` in localStorage and redirects to `/admin/login`. Separate layout wrappers (`AdminLayout.tsx`, `GarageLayout.tsx`) and protected-route components isolate admin/garage/user experiences. API calls go through dedicated service modules: `services/adminApi.ts`, `services/api.ts`, `services/garageApi.ts`.
- Dependency direction: Frontend → backend REST API; backend → Prisma client → SQLite; middleware sits between routes and handlers to enforce role-based access.
