Monorepo with two independent applications sharing a Prisma schema under `backend/prisma/schema.prisma`.

- Backend (`backend/src`): Express 5 server bootstrapped in `index.ts`, which validates required env vars (`JWT_SECRET`, `GEMINI_API_KEY`, `DATABASE_URL`), mounts CORS, serves static uploads from `UPLOAD_DIR`, and registers route groups under `/api/{auth,vehicles,policies,claims,admin,garage/auth,garage,general-chat}`. Each domain is split into `routes/` (Express Router handlers) → `services/` (business logic: payout recalculation, damage analysis, document verification, repair estimates, vehicle detection, policy template seeding) → `utils/prisma.ts` (Prisma client). Middleware in `middleware/` provides role-scoped auth: `auth.ts` (user), `adminAuth.ts` (checks `isAdmin` flag on JWT-decoded user), `garageAuth.ts`, plus `errorHandler.ts` and `multer` upload handling. Startup seeds built-in policy templates via `seedPolicyTemplates` so production DBs start usable.
- Frontend (`frontend/src`): React 19 + Vite app using `react-router-dom` v7 for routing. Three role-based UIs coexist in one SPA: user portal (`/dashboard`, `/claims`, `/vehicles`, `/policies`, `/profile`) wrapped in `ProtectedRoute`; admin portal (`/admin/*`) wrapped in `AdminProtectedRoute` and rendered through `AdminLayout`; garage portal (`/garage/*`) wrapped in `GarageProtectedRoute` and rendered through `GarageLayout`. Shared `context/AuthContext.tsx` holds session state; API calls are centralized in `services/api.ts`, `services/adminApi.ts`, and `services/garageApi.ts`.
- Deployment: backend targets Railway (`railway.toml`) with `prisma db push` at startup; frontend targets Vercel (`vercel.json`).
