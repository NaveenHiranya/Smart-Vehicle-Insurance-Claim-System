Two Express routers are defined: `routes/auth.ts` exposes public `/api/auth/register`, `/api/auth/login` endpoints plus protected `/api/auth/profile` (GET/PUT) guarded by `authMiddleware`; `routes/admin.ts` mounts a single `adminAuthMiddleware` at the router level so every admin route requires both a valid JWT and an `isAdmin: true` user. The two middlewares in `middleware/auth.ts` and `middleware/adminAuth.ts` share the same Bearer-token extraction pattern but differ in enforcement — the generic middleware only verifies the token and attaches `req.userId`, while the admin middleware additionally fetches the user from Prisma and rejects non-admins with 403. Both routers depend on `utils/prisma` for data access and on `../types/index.js` for the extended `AuthRequest` type that carries `userId`. Errors are handled inline per handler with try/catch returning `{ error }` JSON bodies, and no centralized error pipeline is used within this scope.
