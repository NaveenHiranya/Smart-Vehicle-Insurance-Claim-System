Single Express `Router` in `routes/claims.ts` exposes a REST surface (`/api/claims`) with resource endpoints for claims, images, documents, chat, plus workflow endpoints `/submit`, `/analyze`, and `/estimate`. All routes are guarded by `authMiddleware` and enforce per-user scoping via `userId` on every Prisma query. Business logic is delegated to services: `damageAnalysisService.analyzeDamage` reads uploaded images from disk, encodes them as base64 inline data, and calls the Gemini multimodal model to produce a structured JSON damage assessment that is persisted to `DamageAssessment` and propagated back to each `ClaimImage` as `aiAnnotation`; it also lazily imports `repairEstimateService.generateRepairEstimate` to auto-trigger estimates. `claimAssistantService.getChatResponse` builds a prompt context from the claim's vehicle, policy, damage assessment, repair estimate, payout, and document statuses, loads the last 20 chat messages as conversation history, streams the exchange through Gemini, and persists both user and assistant turns to `ChatMessage`. The router depends downward on `utils/prisma`, `utils/gemini`, `types/index`, and sibling services; there is no internal sub-layering beyond this thin route-to-service boundary.
