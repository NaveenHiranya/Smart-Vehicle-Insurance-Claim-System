The module is split into an Express route layer (`routes/claims.ts`) and two domain services under `services/`. The route file defines the full REST surface under `/api/claims`: CRUD on claims, image/document upload via Multer middleware, status transitions (DRAFT → SUBMITTED), damage analysis triggers, repair estimate generation, document verification, and per-claim chat. Every handler enforces ownership by filtering Prisma queries with `userId: req.userId` from the `authMiddleware`, and uses a small `param()` helper to coerce Express 5 params. Business logic is delegated to `damageAnalysisService.ts` (reads claim images from disk, encodes them as base64 inline data, sends them to Gemini with a strict JSON schema prompt, parses the response, persists a `DamageAssessment`, annotates images, and lazily auto-invokes `repairEstimateService`) and `claimAssistantService.ts` (builds a rich context string from the claim, policy, damage assessment, repair estimate, payout, and required documents, then streams a conversation through Gemini's chat API, persisting each user/assistant message). Dependency direction is one-way: routes import services; services import shared Prisma, Gemini client, and types — no cross-import between the two services except the lazy dynamic import of `repairEstimateService` inside `analyzeDamage` to avoid circular dependencies.
