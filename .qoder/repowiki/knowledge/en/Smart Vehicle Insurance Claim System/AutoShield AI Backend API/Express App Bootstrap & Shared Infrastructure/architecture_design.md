The module centers on `src/index.ts`, which is the application entry point: it loads `.env` via `dotenv`, instantiates an Express app, registers global middleware (`cors`, `express.json`, `express.urlencoded`, static `/uploads` serving), mounts domain route modules under `/api/auth`, `/api/vehicles`, `/api/policies`, `/api/claims`, `/api/admin`, exposes a `/api/health` health check, attaches the centralized `errorHandler` as the final error-handling middleware, and listens on a configurable port. Error handling is isolated in `middleware/errorHandler.ts`, which defines a typed `AppError` class carrying a `statusCode` so route handlers can throw structured errors that the middleware serializes to JSON; unhandled errors fall back to a generic 500 response. File uploads are abstracted in `middleware/upload.ts`, which pre-creates `images` and `documents` subdirectories under `UPLOAD_DIR`, configures Multer with disk storage, UUID-based filenames, a MIME-type whitelist (JPEG/PNG/WebP/JPG), and a 10 MB size limit, and exports two named middlewares (`uploadImage`, `uploadDocument`) differentiated by destination folder based on the `fieldname`. Database access is centralized in `utils/prisma.ts`, which instantiates a single `PrismaClient` singleton and re-exports it for reuse across route handlers, avoiding per-request client creation.
