The app is bootstrapped from `src/main.tsx` into a single-page React application whose routing is driven by page components under `src/pages/`. Cross-cutting concerns live in shared directories: `src/context/AuthContext.tsx` provides authentication state consumed by both feature sets; `src/services/api.ts` centralizes HTTP calls used by every page; `src/types/index.ts` defines shared domain models (claims, policies, vehicles) referenced by both the claims feature and the policies/vehicles/dashboard pages; `src/components/Layout.tsx` and `ProtectedRoute.tsx` wrap pages with consistent chrome and route guards. Feature pages are split horizontally — claims-related screens (`ClaimsPage`, `NewClaimPage`, `ClaimDetailPage`) versus policy/vehicle/dashboard screens (`PoliciesPage`, `VehiclesPage`, `DashboardPage`) — but they communicate with the backend through the same API client and consume the same auth context, keeping the two feature groups decoupled while sharing infrastructure.
