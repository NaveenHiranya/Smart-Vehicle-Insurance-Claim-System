The module is split into a thin Express route layer (`routes/claims.ts`) and two domain services under `services/`. The router mounts an `authMiddleware`-protected `Router` exposing the full `/api/claims` REST surface: CRUD on claims, multipart image/document uploads via Multer middleware, status transitions (DRAFT → SUBMITTED), damage analysis triggers, repair estimate generation, document verification, and per-claim chat. Every handler enforces ownership by querying Prisma with `where: { id: ..., userId: req.userId }` before any mutation or read. Business logic is delegated to `damageAnalysisService.ts`, which reads uploaded images from disk, encodes them as base64 inline data, sends them to Gemini with a strict JSON schema prompt, parses the response into a `DamageAssessment`, annotates images, and lazily auto-invokes `repairEstimateService`; and to `claimAssistantService.ts`, which builds a rich context string from claim, policy, damage assessment, repair estimate, payout, and required documents, then streams a conversation through Gemini's chat API while persisting each user/assistant message. Dependency direction is one-way: routes import services; services import shared Prisma, Gemini client, and types — no cross-import between the two services except the lazy dynamic `import('./repairEstimateService.js')` inside `analyzeDamage` to avoid circular dependencies.
