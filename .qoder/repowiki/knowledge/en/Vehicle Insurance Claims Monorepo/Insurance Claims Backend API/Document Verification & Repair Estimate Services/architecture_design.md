Two sibling service modules share a common AI utility layer. `documentVerificationService.ts` exposes `verifyDocument(documentId)`, which loads the Document record (including nested Claim/vehicle/user via Prisma), reads the image file from disk under `UPLOAD_DIR`, encodes it as base64 inline data, and sends it to the Gemini model through `utils/gemini.ts` along with a system prompt describing required checks for driver's licenses, registrations, accident reports, and repair estimates; the LLM response is parsed from markdown JSON blocks into a `DocumentVerificationResult` and persisted back to the Document row. `repairEstimateService.ts` exposes `generateRepairEstimate(claimId)`, which fetches the Claim with its `damageAssessment`, maps each `DamageItem` through lookup-driven calculators (`REPAIR_COSTS`, `LABOR_RATES`, `PAINT_MATERIALS`) to produce `RepairEstimateItem` entries, aggregates totals and estimated repair days, then upserts a `RepairEstimate` and — if a linked policy exists — an `InsurancePayout` reflecting deductible-based coverage. Both services depend only on shared Prisma client, type definitions, and the Gemini helper; they do not import each other, keeping verification and estimation concerns decoupled.
