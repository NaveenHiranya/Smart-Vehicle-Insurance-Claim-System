Two-package monorepo: a Node/Express TypeScript backend under `backend/src` and a React/Vite frontend under `frontend/src`, sharing domain concepts via duplicated type files (`types/index.ts`).

Backend layering:
- Entry point `src/index.ts` bootstraps Express, validates required env vars (`JWT_SECRET`, `GEMINI_API_KEY`, `DATABASE_URL`), mounts CORS, serves static uploads from `UPLOAD_DIR`, registers route groups under `/api/{auth,vehicles,policies,claims,admin,garage/auth,garage,general-chat}`, runs a health check against Prisma, seeds built-in `PolicyTemplate` rows idempotently, then starts listening.
- Routes (`routes/*.ts`) delegate business logic to `services/*` modules (claim assistant, damage analysis, document verification, payout calculation, repair estimate, vehicle detection, policy template seeding) and use shared middleware in `middleware/` for auth (`auth.ts`, `adminAuth.ts`, `garageAuth.ts`), error handling (`errorHandler.ts`), and file upload (`upload.ts`).
- Data access is exclusively through Prisma Client (`utils/prisma.ts`) backed by SQLite (`prisma/schema.prisma`); the schema enforces the vehicle-centric model: `Vehicle` has an optional one-to-one `InsurancePolicy` (unique `vehicleId`), `Claim` ties to `userId`, `vehicleId`, and optionally `policyId`, with enums for `VehicleVerification` (PENDING/VERIFIED/REJECTED), `ClaimStatus`, `SeverityLevel`, `DocumentType`, `VerificationStatus`, and `ImageType`.
- Seeding scripts (`scripts/seedAdmin.ts`, `scripts/seedPolicyTemplates.ts`) bootstrap initial data; `services/policyTemplateSeeder.ts` is invoked at startup to guarantee plan templates exist.

Frontend layering:
- `App.tsx` declares all routes grouped into three role-based sections (user, admin, garage), each wrapped in a dedicated layout component (`Layout`, `AdminLayout`, `GarageLayout`) and guarded by role-specific route guards (`ProtectedRoute`, `AdminProtectedRoute`, `GarageProtectedRoute`).
- Auth state lives in `context/AuthContext.tsx`; API calls go through typed clients in `services/api.ts`, `services/adminApi.ts`, `services/garageApi.ts`. Pages live under `pages/` (user pages, `pages/admin/`, `pages/garage/`). Shared UI components sit in `components/` (layouts, protected-route wrappers, brand panels, AI assistant).
- Build/deploy manifests: `vite.config.ts` + `vercel.json` for the frontend; `railway.toml` plus `.env.example` for both sides.
